# The CumulusMX JSON tag API

What `CumulusMXWeatherClient` depends on, and where each fact came from.  Read on
2026-09-27 from CumulusMX's `master` branch, whose last change to `Cumulus.cs` was
2026-09-16, and from the Cumulus wiki.

## The request

The client asks `http://host:port/api/tags/process.json?rc&temp&hum&...`.
`ApiTagProcessor.ProcessJson` splits the query on `&`, treats each item as a webtag
name, and returns every value as a JSON string: `{"temp":"57.7","hum":"85",...}`.  A
station on 2026-09-22 answered exactly that way.

## Units come from the station, not from the request

CumulusMX serves every figure in the station's own units.  The client asks for the
`tempunitnodeg` and `windunit` webtags and converts from what they name.

- `tempunitnodeg` returns `TempText.Substring(1, 1)`, where `TempText` is `°C` or
  `°F`.  It can only be `C` or `F`.
- `windunit` returns `Units.WindText`, which `Cumulus.cs` sets from the station's
  `WindUnit` setting.  The values 0 to 3 give `m/s`, `mph`, `km/h` and `kts`.  Any
  other value leaves the text unset, and the client refuses it.

Those are the only strings the client accepts, so a metric station needs no test of
its own.  The operator's station cannot switch to metric without damaging its
database, so the source is the only check there is.

## The unit parameter cannot reach the JSON API

`webtags.cs` does convert units on request.  `CheckTempUnit` takes `unit=c` or `f`,
and `CheckWindUnit` takes `unit=mph`, `kph`, `ms` or `kt`.  The wiki page the operator
read on 2026-09-22 does not mention it.

`ProcessJson` cannot pass it.  It builds each tag's parameters from `rc` alone, so a
`unit` in the query arrives as a tag name and never as a parameter.  The parameter
only works in CumulusMX's own templates.  So the client converts, and it would have
to keep converting anyway, because a CSV file keeps the units it started with.

## Decimal commas

`CheckRcDp` formats temperature and wind with `val.ToString("F" + dp)`, which follows
the host's current culture.  `Program.cs` sets a culture only when CumulusMX starts
with `-lang`.  So a station on a German or French machine serves `"20,5"`, and
`float()` refuses it.  Humidity, solar radiation and bearing are integers, and never
carry a decimal separator.

The wiki's local API page documents the fix: "You can specify a special parameter
"rc" (which must be the first URL parameter) to apply the usual remove commas format
to all the tags."  In the code, a leading `rc` gives every tag `rc=y`, and `CheckRcDp`
then replaces each comma with a period.  Anywhere after the first position, `rc` is
read as a tag.

The client puts `rc` first.  On 2026-09-27 the operator's station, which writes
periods already, returned the same JSON with and without it, and did not echo `rc` as
a key.  No comma-locale station has been tried.
