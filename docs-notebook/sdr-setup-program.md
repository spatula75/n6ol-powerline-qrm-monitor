# Shape of the RTL-SDR setup screens

Decisions from September 2026, recorded because several of them are about what was
deliberately *not* built, and a choice not to build something leaves no code behind to
explain itself.

## Two dialogs, not a wizard

The receiver section lists its four steps in order, and each row opens its own thing.
The screen is the ordered list, so a wizard would restate an order the layout already
shows.

They are different interactions.  The gain sweep runs about fifteen seconds, reports a
result and ends.  The offset meter runs until the operator closes it, while they nudge
a number and compare against another radio.  The offset step also happens much later
in practice, because it needs a second receiver on the same antenna, and one combined
flow would mean re-running the sweep to reach it.

## The offset dialog warns, and does not refuse

It would be tidy for the offset dialog to refuse to open until the gain had been
calibrated.  It must not, and the reason came out of measurement rather than taste.

On a quiet antenna the sweep cannot produce an answer at all: the dominance and
headroom bounds cross, and there is no gain that satisfies both.  A dialog that
refused to open until the sweep succeeded would lock out exactly the stations that
most need to set an offset by hand.  Choosing a gain manually and calibrating against
it is a reasonable thing to do, and the stations that have to do it are the ones the
automatic path cannot help.

## No device picker

`device_index` stays a number that somebody types.  A picker would open hardware from
a Textual worker, which is the `pilot.pause()` race `tools/slow_workers.py` exists
for, and it would buy nothing, because enumeration cannot tell two identical receivers
apart.

What enumeration *can* do costs almost nothing.  Measured: 31 ms to count devices
and 37 ms to read the USB strings, and neither opens anything.  On the V4 here that
gives `RTLSDRBlog / Blog V4 / 00000001`, where `rtlsdr_get_device_name` alone gives
only `Generic RTL2832U OEM`.  So the field editor lists what is attached and the
operator types a number against a visible list.  No new screen, no device opened, no
worker, and it helps whenever the receivers differ by model.

Two identical receivers are the case nothing solves.  The serial reads `00000001` on
both unless somebody reprogrammed it, and librtlsdr exposes no bus or port path.  The
honest answer is to try one index and use the other if the wrong receiver answers.

## The source choice sits above the sections

`audio.source` is a row on the main menu rather than a field inside `[audio]`, because
it decides which sections apply at all.  Leaving it inside `[audio]` would bury the
choice in one of the two answers it picks between, and somebody arriving at a menu
wants to know what they are configuring before they start.  It costs one special case
in `main_menu.py`, since every other row there is a section.

## Settings the menu does not show

Five receiver settings are chosen for reasons an operator should not have to hold, so
they carry `x-file-only` and the menu skips them.

They could not simply come out of `schema.json` to achieve that.  Two things depend on
them being there: a test compares the schema's field list against the dataclass
exactly, and `config.example.toml` is generated from the schema, so deleting them
would delete the documentation somebody needs in order to edit them by hand.  A
setting is only editable in a file that explains it.
