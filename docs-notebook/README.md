# Engineering notebook

Working record of technical decisions, measurements and experiments.  It exists so
that a number in the code can be traced back to whatever produced it, months or years
later, when the reasoning has gone from everybody's head.

**This folder contains content written by large language models, and is meant to be
read by them as much as by people.**  That is deliberate.  Much of what ends up here
was produced while working through a problem with an LLM, and the same material is
what an LLM needs to pick the work up again without re-deriving it.  A future session
reading `sdr-gain-calibration.md` starts where the last one finished instead of
measuring the same things over again.

Every file generated by a model says so on its first line.  "Generated by Claude" is
enough.  A reader deciding how much to trust a figure wants to know where it came
from, and a model that wrote a document should not be able to read it back later as
though a person had.

## What belongs here

- Why a constant holds the value it does, with the measurements behind it.
- Experiments and what they ruled out, including the ones that failed.
- Hardware behavior found by testing rather than from a datasheet.
- Design decisions and the options that were rejected.

## What does not

Anything an operator reads.  Tutorials, how-to guides and reference pages live in
`docs/`, which is the published site and has a voice of its own.  Nothing here is
published anywhere.

Release history belongs in `CHANGELOG.md` and project milestones in `HISTORY.md`.

## How it is written

One topic per file, named for the topic: `sdr-gain-calibration.md`, not a date or a
number.  You will come looking for a subject rather than for a week.  Put the date
inside the document instead, beside the measurements it describes, since a figure
without a date is a figure nobody can judge.

The prose rules in `CLAUDE.md` and `docs/ste-writing.md` apply here in full.  Being
an internal record is not a reason to write badly, and these documents are read at
exactly the moment somebody is trying to understand something difficult.

What this folder is exempt from is the approval step: `docs/` needs a human to agree
the wording before it is written, because it is published and has a house voice.  This
folder does not.  Write it down while it is fresh.
